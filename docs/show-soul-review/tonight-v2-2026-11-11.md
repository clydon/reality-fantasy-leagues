## What changed after V1 feedback

| V1 ambiguity | V2 behavior |
| --- | --- |
| Watch along / I've watched it could refer to either episode | Buttons explicitly say **Watch along · E4** and **I watched episode 4**, and carry that episode as the action target |
| Personal progress and game progress can diverge | Game decisions/reveals keep their episode heading. After marking episode 4 watched, those games still say **Episode 4** while the next viewing controls explicitly target **Episode 5** |
| Dates required too much interpretation | **Episode N** is primary, titles appear when available, dates support the identity. Chat and recap destinations name the episode |
| “That last episode” did not jog memory | **Last time · Episode 3** includes boundary-safe recorded moments and participant photos before the reaction prompt |
| An already-posted GIF was not clear enough | **Your GIF is posted**, the person's GIF tile and **Change GIF** replace the missing-reaction prompt. Reloading preserves that state locally |
| “Friday Crew · At your pace” sounded like a special group mode | The header names the couch and offers friends' progress. The intended default is personal-pace play; live-only is an explicit per-game restriction |

The initial captured case is last watched episode 3 / next episode 4; the same numbering logic applies at other progress marks. Episode titles are absent in the real fixture and are not fabricated. “Last week” is deliberately not used for someone several weeks behind or watching an archive.

The summary uses only the recorded last-watched episode within the captured/revealed boundary: in this fixture Jake left medically, Jeremiah was voted out, and Hina won immunity. It does not pull a later broadcast recap or expose fantasy results. If the person advances beyond the captured data or an applicable game's revealed mark, the mock displays a pending recap message instead. Social GIFs and messages remain explicitly illustrative.

## Design reasoning

**Intent:** Give every action an unambiguous object: watch this episode, discuss that episode, reveal this game's episode. Preserve the familiar quick selector and full game destination. A useful reminder precedes a social prompt, and posting changes the prompt into confirmation and editing.

**PFD:** V1 asked the person to infer the target episode from proximity and remember an event from a date. V2 supplies stable identifiers and recognition cues. This is an applied hypothesis using the existing [PFD derivation](perception-first.md), not a measured usability finding. Changes to the hierarchy preserve the first-view action requirements without shrinking controls or hiding overflow.

**Impeccable:** Keep the art, typography and expressive GIF wall. Move friends' progress into the show header, freeing room for the recap. Retain moderate control sizes, the existing palette families, focus return and reduced-motion behavior. Reuse the cached images; no assets were regenerated.

## Own-pace default: intended policy and implementation gap

The user clarified that everyone can play with a couch at their personal pace on the honor system unless the game maker explicitly chooses **Live only**. Pick before watching, watch, then reveal. It is not an exceptional catch-up permission, and it is not a couch-wide mode. The product brief and PRODUCT.md now record this as the governing direction.

This revision changes the review mock and product guidance only. The current server still derives game-level `ownPace` from the starting episode versus aired episodes (`src/lib/server/start-game.ts`), and the engine also has a commissioner's player-level `ownPace` switch (`src/lib/game/state-logic.js`). These mechanisms do not by themselves establish the requested default/explicit-opt-out policy. Do not label every historical `ownPace: false` game an explicitly chosen Live-only game.

A production change needs a deliberate timing-policy representation, legacy-game migration decision, creation/joining defaults, and corresponding authorization, deadline, reveal, draft and synchronization checks. Those changes are outside this one-page design-review revision. No existing game settings or server defaults were changed.

## Decisions

### 2026-11-11 · Explicit episode labels replace date-led actions
- Decided by: user feedback, applied by Codex.
- Why: the person could not tell which episode the actions affected or recall an episode from its date.
- Rejected: making dates the primary identifier, or using “last week” for every viewing pace.
- Rests on: the user's V1 review and APP-REVIEW-DESIGN-BRIEF.md.

### 2026-11-11 · Own-pace play is normal; live-only is a per-game opt-out
- Decided by: user.
- Why: the app is a casual, social place to play honestly at personal pace, while supporting stricter games when explicitly requested by the maker.
- Rejected: a couch-level pace mode or an assumption that personal-pace play requires special permission.
- Rests on: the user's V1 review and PRODUCT.md principle 11.
