# Perception-First Design insight log

### 2026-11-12 — Round 3: make data carry the excitement
**Type:** html
**Domain:** Episode selection, shared viewing position and multiplayer lineup results
**Key finding:** The user distinguishes visual boldness from theatrical decoration: aligned timelines, visible lineups and informative graphs are the desired source of delight. An attractive overview does not replace redesigning the popup it opens.
**Layer(s):** L0/L1/L2/L4
**Promote?:** no
**Notes:** Direct feedback on the prior alternatives, not a population-level finding. Round 3 retains the liked overview, shows the actual chooser variants, puts people and broadcast boundaries on common scales, and compares real starter contributions. Hidden game results stay distinct from visible viewing marks. Connected browser checks validate bounded behavior and return paths, not perceived delight or usability. See ../tonight-data-round3-2026-11-12.md.

### 2026-11-11 — V4: one episode, distinct actions and visible people
**Type:** html
**Domain:** Personal viewing, social pace and episode-wide game reveal
**Key finding:** Last/next labels do not justify separate controls when they open the same chooser. A prominent small decision entry can expose urgency while leaving the episode recap and people ahead of detailed game content.
**Layer(s):** L0/L1/L2/L3/L4
**Promote?:** no
**Notes:** Direct user feedback corrected V3's per-game reveal assumption. V4 makes reveal one episode-wide event, separates readiness from retrospective results, and exposes friends' actual positions before drill-down. Full-screen recap chapters and animated recorded comparisons supply payoff without moving editors onto the overview. Bounded browser checks cover first-view actions, return paths and reduced motion; they do not establish perceived clarity or enjoyment. See ../tonight-v4-2026-11-11.md. Await user review before extending the design.

### 2026-11-11 — V3: game payoff and connected overviews
**Type:** html
**Domain:** Social viewing, game results and episode reveal
**Key finding:** An overview containing only next actions misses the player's reason to return after an episode; results need both visible comparison and a direct path to their causes.
**Layer(s):** L0/L1/L2/L4
**Promote?:** no
**Notes:** User feedback led to contextual metrics and a shared summary/showcase flow. Scope confirmation is distinct from presentation, and a nested detail return preserves the originating comparison/chapter. See ../tonight-v3-2026-11-11.md. This is an applied design hypothesis with bounded browser evidence, not a usability experiment.

### 2026-11-11 — V2: action targets and recognition cues
**Type:** html
**Domain:** Mobile episode companion and casual games
**Key finding:** Proximity to an episode control did not make an unlabeled watch action's target clear; an episode date also failed as a memory cue for reacting.
**Layer(s):** L0/L1/L2/L4
**Promote?:** no
**Notes:** Direct user feedback on V1, not a prevalence estimate. V2 names action targets, preserves distinct game and viewing progress, and supplies a bounded recap plus missing/posted GIF states. See ../tonight-v2-2026-11-11.md. Validate the revision with the user before broader rollout.
