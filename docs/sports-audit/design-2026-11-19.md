# Sports: the design and UX audit (raw material for step 10, "Sports in full")

2026-11-19, read-only, from the code on `docs-cleanup` (dc462ad2), the design-round papers, the plans and BACKLOG. Nothing here is a
design: every "verdict" is marked **for the round to decide**. File references are `path:line`; decisions are
`docs/design-round/decisions.md` by line; DN = the explorer plan's Designs needed (`docs/PLAN-GAMEPLAY-SCENARIO-EXPLORER.md`
§6A, lines 447-504); B = `docs/BACKLOG.md`.

Step 10's scope as PLANS.md states it (PLANS.md:22-23): DN-34 to 39 and 42, B75 and B100, a live game on screen from the existing
poller, and L9's lineup slots for other sports. B175 (BACKLOG.md:553) recommends its own short round after E3 and the stages round.

## 0. The short version

- **What the rounds already carried to sports scale** (each round's "sports check"): the game page's This week and matchup pairs
  by position (step 2c), the draft room's searchable list (step 6), the Players tab as a list plus the athlete sheet (step 5),
  the hub's scoreboard, team marks, the 36-hour hidden final and Watch it as if live (step 7), the Games tab's glance for a
  nine-slot lineup (episode night), and Start a game's gallery through the same screens (wizard bold pass). These are real
  designs and hold.
- **What no round has designed** for a sport: the lineup editor itself (Your moves), the athlete's line (what they did and what
  each stat paid), a slate week laid out by game (TEMP-UI today), a called-off game and a week in progress, categories, a field's
  places, a card's matches, the Episodes tab and the night (B100), the reveal for a sport, sports pushes, waivers at 300 free
  agents, and the live game (no screen; the poller is on no page).
- **Words**: about 40 places read in a show's words; most are words-only fixes (§5).
- **Technical work that comes first**: the game view carries none of categories, places, bouts, per-game slate lines, called-off
  state, or an athlete's opponent/kickoff/bye (game-view.ts:24-42, 119-125); the server scores finals only (score.ts:85-93), so a
  live or provisional display has nothing to read; athletes are keyed by name in the UI and the database (B145).
